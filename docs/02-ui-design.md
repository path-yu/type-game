# 《TypeWake / 词醒》UI 设计规范 v2

> v1 是一套深色游戏风（琥珀 + 近黑）。v2 推倒重做：**Apple HIG 打底 + Material 3 补充**，双主题（浅色 / 深色 / 跟随系统），桌面应用布局。
>
> 配套截图：`shots/ui-{light,dark}-{map,play,card,result,lexicon,review}.png`

---

## 0. 技术选型结论

先回答"有没有现成的 macOS 风格 React 桌面库"——**没有值得用的**。

查了 npm 与生态，实际可用的是**行为原语**，不是成套视觉：

| 库 | 版本 | 定位 | 本项目是否采用 |
|---|---|---|---|
| Base UI (`@base-ui-components/react`) | 1.0.0-rc.0 | Radix 团队 + MUI 维护者的下一代无样式原语 | 观望（RC） |
| Radix (`radix-ui`) | 1.8.1 | 无样式 + 完整无障碍，事实标准 | 候选 |
| MUI (`@mui/material`) | 9.5.0 | Material Design 官方实现 | 否（视觉太"谷歌"） |
| Mantine (`@mantine/core`) | 9.7.4 | 全功能组件库 | 否（风格不统一） |
| Tailwind | 4.3.3 | 原子化 CSS | 否（本项目的样式是手写语义类，够用） |

**结论：视觉问题不是组件库能解决的，是设计系统的问题。** 所以这一版做的是——语义令牌层 + 手写组件样式，行为原语按需引入（当前自研的弹层/浮层已满足需求，暂不引入 Radix，避免一次改动面过大）。

macOS 真正的"材质"（vibrancy）来自系统窗口而非 CSS；Tauri 侧可用 `window-vibrancy` 获得原生模糊，属于后续增强项。当前用 `backdrop-filter` 模拟。

## 1. 从 HIG / M3 各取什么

| 维度 | 取自 | 具体做法 |
|---|---|---|
| 排版层级 | HIG | 六级字号阶梯（28 / 20 / 15 / 13.5 / 12.5 / 11），标题负字距 |
| 间距 | HIG | 严格 4pt 栅格，常用 8 / 12 / 16 / 20 / 24 / 32 |
| 材质 | HIG | 侧栏半透明 + `saturate(180%) blur(28px)` |
| 克制用色 | HIG | 一个强调色（琥珀），其余全是中性灰阶；不用彩色区分功能 |
| 高度语义 | M3 | 4 级阴影，只给"浮起来的东西"用；平面元素用发丝线 |
| 色调分层 | M3 | 浅色：分组底 → 白卡片；深色：底 → surface → surface-2 三级抬升 |
| 状态层 | M3 | hover 用 `--fill` 叠加，而不是换色 |
| 圆角 | 两者折中 | 控件 7 / 卡片 12 / 浮层 16 |

### 2.3 阴影

四层，只给"离页面有距离的东西"：`--sh-1` 卡片 → `--sh-2` hover → `--sh-3` 浮层/toast → `--sh-4` 模态/词卡。
平面区块（列表行、分隔）一律只用 1px 发丝线，不用阴影。

### 2.4 动效

| 场景 | 时长 | 曲线 |
|---|---|---|
| 主题切换 / 布局位移 | 200ms | `cubic-bezier(.32,.72,0,1)`（Apple 标准缓动） |
| 浮层出现 | 220ms | `cubic-bezier(.16,1,.3,1)`，scale .97→1 |
| 按键反馈 | ≤120ms | 无缓动延迟，必须跟手 |
| 按下 | 100ms | `scale(.975)` |

## 3. 双主题

### 3.1 机制

三种模式：`system` / `light` / `dark`，默认 `system`。

- 存 `localStorage["typewake:theme"]`
- 解析后写到 `<html data-theme>` 与 `color-scheme`
- 监听 `prefers-color-scheme` 变化，只有 `system` 模式才跟随
- 侧栏底部单按钮循环切换，显示当前模式（跟随系统 / 浅色 / 深色）

### 3.2 对比度实测

| 组合 | 浅色 | 深色 |
|---|---|---|
| 主文字 / 页面底 | 15.8:1 | 14.2:1 |
| 次文字 / 页面底 | 5.4:1 | 6.6:1 |
| 强调按钮文字 / 琥珀底 | 5.1:1 | 9.8:1 |

均超过 WCAG AA（4.5:1）。

## 4. 布局

### 4.1 外壳：侧栏 + 内容区

```
┌────────────┬──────────────────────────────────┐
│ 词醒        │                                  │
│            │   城市                            │
│ 学习        │   已解锁 1/7 城区 · 掌握 1,000 词  │
│  城市       │                                  │
│  夜巡  12   │   ┌──────────────────────────┐   │
│  藏书阁     │   │ 接着打 …          [开始] │   │
│            │   └──────────────────────────┘   │
│            │   ┌──────────────────────────┐   │
│ 统计        │   │ 1 石阶巷  A1.1  0/8  进入 │   │
│  连续 1 天  │   │ 2 灯火市集 A1.2  0/8  锁定│   │
│  平均 …    │   │ …                        │   │
│  词汇量 …   │   └──────────────────────────┘   │
│ 浅色        │                                  │
└────────────┴──────────────────────────────────┘
```

- 侧栏宽 236px，半透明材质 + 右侧发丝线。窄屏（<900px）收成 64px 图标栏。
- 内容区最大宽 940px 居中，外边距 32 / 40。
- **专注模式**：进入打字 / 夜巡时侧栏收起到 0 宽，内容区占满整屏。这是 HIG 里"进入沉浸式任务"的标准做法。

### 4.2 为什么去掉顶部导航

v1 的顶部胶囊导航是 web 产品的形态，放在桌面应用里显得"是个网页"。侧栏（source list）是 macOS 应用的标准骨架，同时能容纳统计与设置入口——信息密度更高，也更像"应用"。

### 4.3 为什么砍掉"城市地图"

v1 画了一张星图 SVG，深色下发光的点阵在浅色下没法看，而且和下方的城区列表**信息完全重复**。

v2 直接换成列表：编号 + 名称 + 难度档 + 进度条 + 状态。同样的信息，扫读效率高一个数量级，两套主题都能成立。世界观的叙事交给文案（"接着打""已点亮 n/8"），不靠插图。

## 5. 逐屏要点

### 5.1 城市（Home）

- 页头：28px 标题 + 一行统计 + 右侧连续天数胶囊
- **Hero 卡**：当前推荐卷轴（标题用 Lora 衬线，元信息一行，右侧主按钮）。全页唯一的高饱和元素就是那个琥珀按钮，视线自然落点。
- **城区列表**：7 行，行高 13px 内边距，编号方块区分状态（进行中=实心琥珀 / 已完成=琥珀浅底 / 锁定=灰底）。进度条只在右侧占 92px，不喧宾夺主。

### 5.2 打字（专注模式）

- 顶部信息条默认 62% 不透明度，鼠标移入恢复到 100%
- 文字区 680px 宽、25px 等宽、行高 56px、3 行可视
- 打对的字淡到 `--type-done`（浅色是浅灰，深色是深灰）——"墨迹风干"
- 光标 2.5px 琥珀，1.5s 呼吸
- 连击光带在左边缘 26px 处，2px，透明度 0.3 并做上下渐隐——**不做成一条硬线**，否则看起来像 UI 故障
- 右侧 COMBO / ACCURACY 在打字时淡到 45%，避免和文字抢注意力

### 5.3 词卡浮层

340px 卡，`--sh-4` 阴影，圆角 16。内容顺序：词（Lora 20px）+ 音标 → 中文释义（14px）→ 英文释义（Lora 12.5px 灰）→ 发丝线 → 频段/标签 → 两个按钮。底部"查词时计时已暂停"用绿色圆点提示。

### 5.4 结算

居中布局：星（28px 矢量四角星，逐个弹入）→ WPM 大字（56px 等宽）→ 一行指标 → 新词胶囊 → 城区进度 → 三个按钮。星用 SVG 而不是字符 `✦`，避免不同系统字体下变成方块。

### 5.5 夜巡

题卡是这一版新增的容器（560px，白卡，`--sh-2`）：
- 顶部题型标签（根据释义 / 听发音 / 根据英文释义）
- 中间题目（22px 细体）
- 下面字母槽（32px 等宽，当前槽有琥珀浅底）

**出题策略也改了**：只要词条有中文释义就考"看中文打英文"。v1 用英文释义出题，碰上 `conj.` 这类虚词会得到 "r and nothing more" 这种没法答的题干。

### 5.6 藏书阁

大数字 40px 等宽 + 五段 Tier 分层条 + 胶囊筛选 + 卡片网格（172px 起）。
**"点亮"只在真正打过（`seen > 0`）且掌握度 ≥70 时才出现**，且只描边不刷底色——v1 因为先验值让所有 Tier1 词全亮成一片琥珀。

### 5.7 空状态

统一结构：淡图标 + 一句说明 + 一个行动按钮。不用插画，不用表情堆砌。

## 7. 无障碍

- 正文对比度 ≥ 5.4:1，主文字 ≥ 14:1（见 §3.2）
- 错误状态不只靠颜色：还有底部波浪线 + 抖动（形状冗余）
- `prefers-reduced-motion` 下关闭所有动效，只保留颜色变化
- 焦点环全局统一，键盘可达
- 快捷键：`Enter` 开始 / 再来一条，`Cmd/Ctrl + 1/2/3` 切页，`Esc` 暂停
- 侧栏在浅色下用 `rgba(244,244,248,.78)` 叠加，保证即使不支持 `backdrop-filter` 也有底色

## 9. v3 增量（2026-11-01 晚）

### 9.1 词卡：发音速度改成真菜单

v1 那个 `0.6×` 按钮其实是个"慢速播放"快捷键，点下去只出声、不出选项——语义误导。改成：

- `🔊` 播放
- `1×` 打开下拉：0.5× / 0.75× / 1× / 1.25×，选中项高亮，写回 `settings.rate`
- 点外部或 Esc 关闭；Esc 在菜单打开时先关菜单，再关卡片

**踩坑记录**：`.card .spk button` 这个后代选择器把菜单里的按钮也一起套成了 27×27，导致文字换行重叠。改成 `.card .spk > button` 直系选择器。

### 9.2 新增设置页

侧栏底部「设置」，四组：

| 组 | 项 |
|---|---|
| 外观 | 主题（跟随系统/浅色/深色）、减少动效 |
| 发音 | 口音（美音/英音）、发音速度、**打字时朗读单词** |
| 打字 | 键盘音效 |
| 关于 | 数据来源与许可 |

控件只有两种：**分段控件**（`.seg`，用于互斥选项）和**开关**（`.switch`，用于布尔）。选中态用白色浮起 + 阴影，符合 HIG 的 segmented control 语义。

「减少动效」原来是个假开关，现在真的会给 `<html>` 加 `.no-motion`，全局禁用 animation / transition。

### 9.3 打字时实时朗读

`TypingEngine` 增加 `onWordEnd(key, raw)` 回调，每打完一个整词触发。`PlayScreen` 里接成：

- 开关关闭 → 直接 return
- 跳过长度 < 3 的词（a / of / the 读出来只会干扰节奏）
- 260ms 节流，避免 TTS 排队把声音拖到几秒之后

### 9.4 夜巡重做为「听写」

**原设计的问题**（用户反馈"设计太奇怪、为什么重复显示同一个词"）：

1. 队列只取"今天到期"的词，新用户往往只有 1–2 个 → 打开就是"1/1 记住了"，像 bug
2. 没有会话概念，答完立刻结束，用户感知不到"练了一批"
3. 三种题型随机切换（看中文 / 听音 / 看英文释义），节奏断裂
4. 答错的词 `due` 设为明天，但列表天天重算，同一个词反复出现在最前面

**新设计**：

- **一轮 12 个词**，从三档池子里按优先级补满：到期 → 掌握度 <50 → 打错过 → 收藏过
- **只有一种题型：听写**。进来直接播发音，你把它敲出来；想不起来点「看提示」看中文，不算错
- 每个词一轮只出现一次，答完给出正确拼写 + 释义 + 再播一遍
- 结算页：`n / N 拼对了` + 答错的词做成可点击的胶囊（点一下重播）+「再来一轮 / 回城市」

这样"复习"从"单题问答"变成了"一次练习"，也顺带满足了"边播音频边打字"的需求。

### 9.5 句子解析条（打字界面）

需求：每篇文章都要能看到"当前这句在说什么"，并且可以在设置里切换。

**分两层实现**：

| 层 | 覆盖 | 来源 | 是否离线可用 |
|---|---|---|---|
| 句子生词解析 | **100%（1156 篇全覆盖）** | 本地从 ECDICT 实时计算：按句切分 → 取 Tier≥3（或 Tier2 且长≥6、词库外且长≥5）→ 附中文释义 | ✅ |
| 整句中文译文 | 按 `public/data/tr.json` 覆盖率 | `scripts/translate.mjs` 调 MyMemory 补齐 | ✅（已内嵌） |

**为什么生词解析放在运行时算**：如果预生成，1156 篇 × 6 句 × 5 词 ≈ 3.5 万条，JSON 会从 780KB 涨到 2MB+；而这些信息本来就能从已加载的 7200 词词库里现算，零成本、零体积。

**为什么译文必须预生成进数据**：MyMemory 没有返回 `Access-Control-Allow-Origin`，浏览器直连会被 CORS 拦。所以只能构建期跑脚本，产物随包分发。

**交互**：光标移动跨句时自动切换；生词做成胶囊，点一下朗读该词。设置页三档：`关闭 / 生词 / 生词+译文`，默认"生词"。

### 9.6 词形与原形的展示修正

问题：点 `carries` 弹出的是 `carry`，用户会觉得"词和解析对不上"。

原因：点击时传的是 lemma（用于查词库），卡片直接把 lemma 当词头显示。

修法：点击同时传 `surface`（界面上的词形）和 `key`（原形）。卡片词头用 `surface`，音标后面追加一枚 `原形 carry` 的琥珀色小标。查词、发音、收藏仍然走 lemma，所以同一个词的掌握度不会因为词形变化被拆成好几份。

### 9.7 词卡：点外部关闭

弹出的词卡原先只能按 Esc 或点「关闭」按钮收起，点画布其它位置没有反应——用户的第一反应是「点一下空白处」，落空就会觉得控件坏了。

实现：`pointerdown` + **捕获阶段**监听在 `document` 上。

| 落点 | 行为 |
|---|---|
| 卡片内部 | 忽略（按钮各司其职） |
| 另一个词（`.w`） | **忽略**，交给点击逻辑换词 |
| 其它任何位置 | 关闭并恢复计时 |

用 `pointerdown` 而非 `click`，是为了比打字区的点击处理更早拿到事件；用捕获阶段，避免被内层 `stopPropagation` 吞掉。

第二条规则是必须的：如果点另一个词也走「先关再开」，引擎会 `resume()` 一次又立刻 `pause()`，计时器白抖一下，而且卡片会闪一帧。测试用例专门覆盖了这个分歧。

### 9.8 每日卷轴卡片

位置：地图页「接着打」hero 之下、城区列表之上。它要在**不抢主 CTA** 的前提下每天都被看见——
所以做成一条横向行而不是第二张大卡：主操作仍然只有「开始打字」一个实心按钮。

| 元素 | 规格 |
|---|---|
| 左侧标记 | 28px 圆，未完成是 `✦`（浅琥珀底），已完成换 `✓` 实心琥珀底白字 |
| 标签 | `今日卷轴 · 2026-11-01`，10px / 600 / 0.08em 字距，第三级文字色 |
| 标题 | 15px 衬线 600，单行省略——书名用衬线跟正文的等宽形成对比 |
| 元信息 | 城区 · 主题 · 词数 · 生词数（完成后追加「今日最好 N WPM」） |
| 右侧 | 胶囊 `开始` / `再打一次`，浅琥珀底、品牌色字，不用实心按钮 |

三点设计判断：

1. **不用实心按钮**。地图页如果出现两个实心 CTA，视线会分裂；每日卷轴是「附加选项」，用胶囊表达层级。
2. **完成后不消失**。换成 ✓ + 成绩 + 「再打一次」，既确认完成，也允许重打刷成绩——直接隐藏会让人怀疑是不是点没了。
3. **WPM 上限保护**。只有 ≤300 才显示成绩。上限不是洁癖：脚本或自动化输入会算出几千 WPM，直接显示会让人以为数值系统坏了。

### 9.9 连续天数与明日预告

v1 只做到「今天打这一篇」，缺一个「明天还回来」的理由。补了两处：

**连续天数（独立于总连胜）**

原来的 `streak` 是「任意练习日」，完成一篇普通文章也算。这会让「每日卷轴」在数据上毫无分量。
现在拆成两个：

| 字段 | 含义 | 触发条件 |
|---|---|---|
| `streak` | 总练习连胜（顶栏「连续 N 天」） | 当天任意一篇 |
| `dailyStreak` | 每日连续（卡片上的「连续 N 天」） | **只有完成当日卷轴** |

判定逻辑三个分支：昨天完成过 → +1；今天已完成再打 → 不变（不刷分）；更早 → 归 1。
显示时用 `aliveDailyStreak()`：昨天完成过但今天还没打，仍然显示天数（不算断签），只有隔了一整天以上才归 0。

**明日预告**

完成后在卡片底部加一行 `明日 · <标题>`。标题用同一个 `pickDaily` 算明天的日期得到——纯本地计算，不需要后端。
它的作用不是信息量，是**钩子**：今天的事做完了，但屏幕上出现了一个「明天的」具体名字，比任何「明天再来」的文案都具体。

结算页徽章也随之改成按 `dailyStreak` 显示（第 1 天显示「今天的第一篇」，避免「连续 1 天」这种别扭措辞）。

### 9.10 体检报告

侧栏「体检报告」，把 `runs.jsonl` 之外还留在本地的数据（最近 60 次成绩、累计易错键对、词掌握度）压成可执行结论。

**核心原则：报告必须给判断，不能只列数据。**
「准确率 91.2%，WPM 43」用户自己也会看；「你的瓶颈是准确率，不是手速」才需要分析。所以页面第一块是**诊断卡**，四档判定按优先级短路：

| 条件 | 结论 | 语义 |
|---|---|---|
| 平均准确率 < 94% | 瓶颈是准确率，不是手速 | 改错要停下重找位置，这才是慢的原因 |
| 一致性 < 55% | 节奏不稳：忽快忽慢 | 匀速 40 比忽快忽慢 50 更省力 |
| 平均 WPM < 城区目标 | 准确率够用，速度还差一段 | 差多少词/分钟直接写出来 |
| 其余 | 状态很好 | 可以往更难的城区走 |

按优先级短路是关键：一个人可能同时「准确率低 + 节奏乱」，但一次只该给他一个改进重点。

**易错键对**：引擎在打错时记录 `应打\u0000实打`，累计进 `keyErr`。报告按次数排序取前 8，用 `kbd` 呈现「e → r」。
这比「哪些字母错得多」有用——它指出的是**固定的手指混淆**，改一个就见效。

**折线**：最近 30 次 WPM，`viewBox` 拉伸 + `vector-effect: non-scaling-stroke` 保证线宽不随容器变形。

**反复打错的词**：按 `er` 降序、`m` 升序取 8 个，点击朗读。它和夜巡共用同一份掌握度数据，不是另造一套。

**速度合理性过滤**：统计时剔除 >300 WPM 的记录（人类纪录约 210）。脚本或自动化输入会算出几千 WPM，
混进平均值会让整页结论失真——本地单人工具没有反作弊，只能靠阈值兜底。

### 9.11 阅读填空

布局：标题（城区 · 书名 · 空数）+ 工具行（城区下拉 / 提示三档）+ 进度条 + 正文卡片 + 底部两个按钮。

三个关键决定：

1. **空位是内联输入框，不是列表**。练习的价值在于上下文，所以正文必须连成一个视觉整体：
   输入框宽度按答案长度给（`ch` 单位），行高 2.1 保持阅读节奏，衬线正文 + 等宽输入形成对比。
   `box-sizing: content-box` 是必须的——用 border-box 时 padding 会吃掉 `ch` 宽度，词尾被截成 `cours…`。
2. **作答前就能看到词的轮廓**。输入框宽度等于答案长度，等于免费给了"这个词几个字母"的提示。
   这是刻意的：填空题该考"填什么"，不该考"猜长度"。
3. **提交后锁定**。输入框 `disabled`，错误处红字带删除线、旁边紧跟绿色正确答案——
   一眼能看出"我写了什么 / 应该是什么"，不用来回对应。

### 9.12 词汇量数字的表述修正

**现象**：藏书阁显示「978 词 · 已掌握词汇量」，用户问「为什么是 978，不是整数？」

**根因**：这个数字不是测出来的，是 `estimateVocab()` 遍历 7200 词按掌握度 ≥70 计数，而
**没碰过的 Tier1 词用词频先验直接记 70**（`priorOf`：Tier1=70 / Tier2=45 / Tier3=25 / 其余=10）。
Tier1 恰好 1000 个 → 新玩家一进来就是「已掌握 1000 词」。

978 = 1000 − 22。那 22 个是练过的 Tier1 词，被打错（−8）、查词（打回 25）或填空填错（−8）压到 70 以下。

**问题不在数字，在说法**：「已掌握」暗示这是实测结果，实际上 98% 是先验。

改法：

| 位置 | 原文案 | 新文案 |
|---|---|---|
| 大数字下方 | 已掌握词汇量 · 词库共 7,200 词 | **估算**词汇量 · 实测 N · 先验 M · 练习中降级 D · 词库共 7,200 词 |
| 地图页副标题 | 掌握 978 词 | 词汇量 978 词 |

`vocabBreakdown()` 返回 `{ total, measured, prior, demoted }`，把「哪些是打的、哪些是估的、哪些被降级」摊开。
用户看到「实测 2 · 先验 978 · 练习中降级 22」，就不会再问"为什么少了 22 个"——
**能解释的数字比好看的整数重要**。

**整句中文提示（焦点随动）**

填空最难的往往不是"这个词什么意思"，而是"这句在说什么"。所以正文下方加了一条随焦点变化的译文：

```
[第 1 句] 哦，我不只是说那棵树；它当然可爱——是那种亮堂堂的可爱——它开得好像当真是有心开给你看的——
```

数据来自 `tr.json`（已 100% 覆盖），按 `blank.sentence` 取对应句。三个约束：

- **只在「首字母+释义」档出现**。否则「无提示」档也会看到译文，设置自相矛盾。
- **跟着焦点走**，不按句罗列。一次只显示当前这一句，避免整篇译文把题做完。
- **提交后消失**。答案都出来了，再看中文没有意义。

顺带删掉一个噪音：完整提示档里每个空后面的 `?` 气泡。那一档已经在 placeholder 里给了首字母和释义，
再放一个"看提示"按钮只是视觉干扰——`?` 只属于「首字母」档（那一档确实还缺词义）。

# 08 · 场景对话：把「读得懂」补成「说得出」

前面十一轮做的都是**输入侧**：1179 篇文章练认词、练手速、练句子结构。
但读得懂一篇 Moby Dick，和能在咖啡店顺利点一杯咖啡，是两种能力。
这一层补的就是后者。

---

## 1. 为什么是「对话」而不是又一套文章

| | 文章（已有 1179 篇） | 场景对话（新增 10 场） |
|---|---|---|
| 语言 | 19 世纪书面语、维基说明文 | 当代口语 |
| 单位 | 段落 | 一来一回的话轮 |
| 练的是 | 认得出、打得快 | 轮到自己时**能接上** |
| 结构 | 作者写的，不能改 | 有固定套路，可复用 |

口语和书面语的差距，不是「简单一点的英语」。举两个这一批语料里真实存在的例子：

```
Tell me about it.        不是「跟我说说」，是「太对了」
Will that do?            不是「那会做吗」，是「这样行不行」
What brings you in?      医生的开场白，不是「什么把你带进来了」
That'll be fifty cents.  店员报价，听到就知道该掏钱了
```

这些句子每一个词都认识，连起来就是听不懂。文章里不会出现，因为 19 世纪的小说人物不去咖啡店点单。

## 2. 语料

10 场 / 96 句 / 48 句是你的台词 / 40 个句型 / 24 条用法提示 / 975 词。
全部手写，没有用生成器，也没有翻译源 —— 中文是我逐句写的，口语体的中文。

| 场景 | 难度 | 训练点 |
|---|---|---|
| 街头问路 | A1 | 向陌生人开口的第一句 |
| 咖啡店点单 | A2 | Could I get… / For here or to go |
| 电梯里的寒暄 | A2 | 闲聊怎么开场、怎么接 |
| 机场值机 | A2 | 托运、座位、登机口 |
| 酒店入住 | A2 | 预订、含早、延迟退房 |
| 餐厅点菜 | A2 | 推荐、忌口、结账 |
| 退换货 | B1 | refund / exchange、试穿 |
| 看医生 | B1 | 描述病程、过敏、医嘱 |
| 求职面试 | B1+ | 自我介绍、缺点、反问 |
| 客服电话 | B1+ | 订单号、物流、补发 |

每条台词可以带一条 `note`，写的是**为什么这么说**，不是释义：

> `get started for you` 是美国咖啡店的固定问法，字面是「开始给你做」。不是问你要不要开始。
>
> `Tell me about it` 不是「跟我说说」，而是强烈赞同 ＝「太对了」。
>
> `aisle` 读 /aɪl/，s 不发音。

## 3. 五种练法是一条阶梯

同一份稿子，五个 tab：

| 模式 | 屏幕上有 | 认知负荷 | 对应理论 |
|---|---|---|---|
| **通读** | 英文 + 中文 + 注释 | 最低 | 可理解输入 |
| **跟打** | 英文原句（逐字符高亮） | 中 | 抄写 + 语音回路 |
| **背打** | 只有中文 + 词长空位 | 高 | 提取练习（retrieval practice） |
| **跟读** | 英文 + 麦克风 | 高 | 产出性练习（production） |
| **实战** | 只有中文 + 对方的话 + 一个意外 | 最高 | 迁移（transfer） |

跟打和背打共用同一个组件，只差一个 `shown` 判断。这不是省事 ——
**它们本来就该是同一个动作的两次难度**：先照着打建立肌肉记忆，再把英文撤掉逼自己提取。

跟读是另一套：输入源从键盘换成了嘴。见第 9 节。

背打的空位按词长画，不是一个一个的点：

```
我要一杯大杯拿铁，谢谢。
_____  _  ___  _  _____  _____  ______
```

比 `· · · · ·` 有用得多 —— 词数和词长是最基础的脚手架，又不泄露任何一个字母。
卡住了点「看首字母」：

```
C I g a l l p
```

## 4. 判分：宽在哪、严在哪

### 宽：标点、大小写、撇号、连字符

```js
diff("Could I get a large latte, please?", "could i get a large latte please")  // true
diff("I'm checking in.", "im checking in")                                    // true
diff("a front-end role", "a front end role")                                  // true
```

对话练习考的是「能不能把这句话说出来」。因为少一个逗号被判错，用户学到的是
「我很笨」，不是「这句话怎么说」。归一化时只留下字母和数字，其余全部丢掉。

### 严：一个字母都不放过

```js
diff("Could I get a large latte, please?", "Could I get a large latto please")  // false
```

打错就是打错，因为**口语里发错一个音，对方就听不懂**。

### 错的位置要能回推成词

判错之后不能只说「错了」。逐字符比对拿到错位下标，再映射回「这是第几个词」：

```js
const d = diff(target, typed);            // { ok: false, wrong: [13] }
errorWords(target, d.wrong);              // ['large']
```

只把**出错的那几个词**交给学习引擎。整句八个词全记一遍错误，
掌握度就被稀释成噪音，夜巡也会被灌满。

三条过滤：

1. 长度 < 4 的不记（`get` / `the` 错了不值得单独复习）
2. 虚词不记（一张 40 词的停用表，外加 `could / would / please` 这类口语填充词）
3. **词库里没有中文释义的不记** —— 记了也只会在夜巡里显示「词库未收录」，是一张空牌

第 3 条踩过坑：`That's` 早期被拆成 `thats`，词库查不到。现在撇号保留在词里，
判词时去掉所有格 `'s` 再查（`Monday's → monday`）。

## 5. 界面上的四个决定

**① 气泡左右分栏。** 你的话靠右（浅琥珀底），对方靠左（白底带边）。
对话的物理形态本身就是信息 —— 谁在说、说到第几句，一眼看得出来，不需要读名字。

**② 练习区垂直居中。** 打字时视线应该落在屏幕中段，不是页顶。
`.dg-main` 给了 300px 最小高度，内容在其中居中。

**③ 答错不换页，原地亮答案。** 正确句逐字符标色：

- 绿色：你打对的
- 红色波浪线：打错的
- 虚线：漏掉的

比弹一个「❌ 错误」有用 —— 用户需要看见**差在哪一个字符**。

**④ 输入框绝不能 `disabled`。** 这是本轮唯一一个真 bug：

React 里把 input 设成 `disabled`，它立刻失去焦点，**键盘事件再也收不到**。
于是「答错后回车继续」在最需要它的时候失效 —— 用户只能拿鼠标去点别处再回来。
改成 `readOnly` + `onChange` 拦截，焦点留在原地，回车照常工作。

## 6. 与学习引擎的衔接

练完一场，两件事写进档案：

```js
finishScene(sceneId, score, failedWords, as)
  ├── p.scenes[sceneId] = { best, swapBest, liveBest, at, runs }
  │     as = 'you'   → best      说自己的台词
  │     as = 'other' → swapBest  换角，说对方的台词
  │     as = 'live'  → liveBest  实战，整场含岔路的接住率
  └── 每个错词 gradedWord(...)                    // 掌握度 + FSRS 排期，当晚进夜巡
```

三项成绩分开记，因为它们是三种能力：**照着说**（best）、**替对方说**（swapBest）、
**没人给稿子时接住**（liveBest）。混成一个数字，就等于把三者抵消。

`gradedWord()` 是这一轮新抽出来的：夜巡、预习卡、场景对话原来各写了一遍评分逻辑
（掌握度 -20、FSRS 记 Again、当天回炉）。三份代码迟早会有一份漏掉「答错当天回炉」。
现在只有一份。

### 报告里的位置

练过对话之后，体检报告会多出一块「场景对话」：

```
场景对话                      练过 4 / 10 场 · 换角 1 场 · 实战 3 场
┌─ 说台词 83% ──────┐  ┌─ 实战接住率 52% ──┐
│    基本能说下来    │  │     还接不顺      │
└───────────────────┘  └───────────────────┘
台词背得下来，临场接不住
说台词最好 83%，实战接住率只有 52%。差的不是发音也不是词，是没人给稿子时想不出怎么接。
```

判定只在**两样都练过两场以上**时才下结论——一场的分差说明不了任何事。
三种结论文案：

| 条件 | 结论 |
|---|---|
| `best - live ≥ 20` | 台词背得下来，临场接不住（并往建议里塞一条「专挑岔路练」） |
| `live < 60` | 实战还没上手，先回背打 |
| `best - live ≤ 8` | 既能背也能接 |

没有对话数据时整块不渲染——报告里不该出现一堆 0。

## 8. 跟读：输入源换成麦克风

「跟打」证明你能把句子敲出来，「背打」证明你能想起来，但两者都不检验**发音**。
跟读用的是浏览器自带的 `SpeechRecognition`：

```ts
const rec = new SpeechRecognition();
rec.lang = 'en-US';
rec.onresult = e => scoreSay(target, e.results[0][0].transcript);
rec.start();
```

### 判分按词，不按字符

识别器的输出天然带噪：口音、连读、专有名词。如果拿字符级 `diff()` 去比，
「说得很好但识别错一个词」会被判成灾难，用户只会觉得这功能坏了。

所以用**最长公共子序列按词对齐**：

```ts
scoreSay('Iced, please. And could you make it with oat milk?',
         'Iced please and could you make it with milk')
// → 8 / 9 个词对上，pass
```

三条规则：

1. **缩写展开**：识别器常把 `I'm` 写成 `I am`，两边都展开成 `i am` 再对齐
2. **长词容一个字母**：`iced / ice`、`latte / lattes` 算对；`cat / car` 不算 ——
   只有较长的一边 ≥4 字母才放宽
3. **容 20% 的词没听清**：`allow = floor(n / 5)`。3 个词的短句容 0 个，
   10 个词的句子容 2 个 —— 短句漏一个就是漏了一半意思

判错时不只报错，逐词标出来：绿底是通过的词，红底带删除线是没听清的词。
底下还回显「听到：hello there how are you」—— 用户能立刻判断是**自己说错了**
还是**识别器听岔了**，这个区分决定了他是重说还是骂工具。

### 降级是必须的

`SpeechRecognition` 在 Chrome 能用（识别走 Google 的服务器），
在 Tauri 的 WebView2 里**没有这个 API**。桌面端用户点开会是一片空白 ——
所以 `asrSupported()` 是一等公民：

```
这个环境跑不了语音识别
浏览器版 Chrome 支持（识别在 Google 的服务器上做）；桌面端 WebView2 不支持。
可以先「听原句」建立声音印象，再切到跟打。
[回到场景列表] [听原句] [改用跟打]
```

错误码也翻译成人话：`not-allowed` → 「麦克风被拒绝了，需要在浏览器地址栏允许麦克风」，
`network` → 「识别服务连不上」，`no-speech` → 「没听到声音，再按一次试试」。

### 只记「真的没说清」的词

跟读是识别器的判断，不是用户的自我报告。所以只有一个门槛：**匹配率 < 60%** 才把
没对上的词记进夜巡。20%~60% 之间不记 —— 那更可能是识别误差，不该让用户为工具的错误
背单词。这条规则写在 `Speak.skip()` 里，测试也守着。

### 测试怎么跑

无头浏览器既没有麦克风，也连不上 Google 的识别服务。`src/lib/asr.ts` 留了一个
**显式的注入点**：

```ts
// 测试里：
await p.evaluate(() => {
  window.__nextSay = 'Could I get a large latte, please';
  window.__TYPEWAKE_ASR__ = () => window.__nextSay;
});
```

`asrSupported()` 与 `createAsr()` 先看这个钩子，再看真实构造器。
这样跟读的整条链路（点击 → 识别 → 判分 → 翻页 → 结算）都能在 CI 里跑，
而不用假装「测了」。

降级路径同样是真测的：`delete window.SpeechRecognition` 之后再进跟读，
断言出现说明卡片、并且「改用跟打」能切过去。

## 9. 角色互换：练对方的话轮

前八节写的都是「练你自己的台词」。但真实对话里有一半的难度在**听懂对方说了什么**，
再决定怎么接。只练自己的话，对方的台词永远只是背景板 —— 看着眼熟，听着发懵。

### 实现只有一处

```ts
export function linesOf(scene: Scene, as: Role = 'you'): DLine[] {
  return scene.lines.filter(l => (as === 'you' ? l.r === scene.you : l.r !== scene.you));
}
```

练习模式（跟打 / 背打 / 跟读）顶部多一个开关：

```
练谁   [你 · 5 句] [店员 · 5 句]   换角：先听懂对方说什么，再替他说出来
```

换角色时 `key` 带上角色，组件整体重挂载 —— 进度、错词、结算全部清零，
不会出现「练到第 3 句，换个角色接着从第 3 句开始」这种错位。

### 成绩必须分两本账

`SceneStat` 因此多了 `swapBest`：

```ts
{ best: 88, swapBest: 71, runs: 4 }
```

如果不分开：换角打了满分会把「你」的 88% 刷成 100%，而这两个成绩证明的是完全不同的能力。
卡片上对应两个标记：

| 状态 | 显示 |
|---|---|
| 只练过自己 | `✓` + 「最好 100%」 |
| 只练过对方 | `✓✓` + 「换角 92%」（不显示空的 0%） |
| 两个都练 | `✓✓` + 「最好 88% 换角 71%」 |

`✓✓` 是这场对话的真正完成标记 —— 两个方向都能走通，才算拿下了这个场景。

### 语料的对称性

换角要求每场对方的台词也够练。`validate()` 现在只强制「你的台词 ≥3 句」，
测试另外断言了对方也 ≥3 句（当前 10 场分布是 4/4 或 5/5，最均衡的一种写法）。

## 10. 岔路：对方不按剧本说话

前九节有一条共同的隐含前提：**对方会照着剧本说**。真实对话里不会。
店员会说「卖完了」，路人会说「那家关了」，面试官会说「太笼统，举个例子」。

### 结构：一条能被 validate 强制的约束

岔路不是随便插一段，它必须满足三条：

1. 接在**你的**某句台词之后（`at` 指向那句）
2. 紧接着那句**对方**的台词会被 `react` 顶替 —— 两条应对各自有各自的反应
3. 再往后必须接回**你的**下一句

第 2、3 条是关键。如果 `react` 不顶替下一句，就会出现「你说完现金的事，对方还在问要不要燕麦奶」的断裂；
如果后面接不回你的台词，这段对话就没有出口。

```ts
export function timelineOf(scene: Scene): Step[] {
  // 岔路接在第 at 句之后，同时吃掉 at+1（对方的台词）
}
```

这条约束由 `validate()` 强制执行，测试里也断言了「岔路顶替一句台词，所以总步数＝台词数」——
写语料时想偷懒插在对方台词后面，`npm test` 会当场拦住。

### 实战：给目标，不给说法

```
      岔路 · 对方没按剧本来
            店员说
  So sorry, the card machine is down. It's cash only today.
        抱歉，刷卡机坏了，今天只收现金。
     ⓘ down 在这里是「坏掉、不能用」，不是「往下」。

      你的目标 · 收银台出了状况，给出一个能继续走下去的解决方案

     [ 用一句英语接上去，回车确认 ]
```

注意屏幕上没有英文答案，只有中文目标和对方的原话。这是实战和前几种模式的核心差别：
跟打有原文可抄，背打有中文可对，实战只有一个**意图**。

判定复用跟读的 `scoreSay`（按词对齐、容 20%、长词容一个字母），阈值 0.7：

- ≥ 0.7 → 「岔路 · 你接住了」，对方按更接近的那条路反应
- < 0.7 → 亮出两条参考说法，挑一个继续（不计分）
- 还有个「想不出来」的按钮，直接跳到选项，不逼人卡在那里

**为什么不一开始就给选项**：能选不等于会说。选项只在失败之后出现，是退路不是题目。

### 已知局限

只有两条参考说法。语义对但措辞不同的自创句子会被判「没接住」——

> 你打：I'll just pay cash.  （完全正确）
> 判：没接住，因为两条参考说法是 "That's fine, I've got cash." 和 "Could I pay by phone instead?"

所以必须有退路，而且退路不能算分。真正的开放评分需要语言模型，这在离线的桌面应用里不现实；
与其假装能评判，不如老实承认这是「两种说法的训练」。

### 成绩

`typedSteps(scene)` = 你的台词 + 1（岔路）。结算显示「6 处开口，接住 5 处」——
比「打对了几句台词」更贴近真实对话的体验：你不是在背台词，是在一轮一轮地接话。

### 类型：为诊断而分类

每处岔路带一个 `kind`，十场覆盖五种意外：

| kind | 中文 | 场景 |
|---|---|---|
| `short` | 东西没了 | 三文鱼卖完 / 没有 M 码 / 那家药店关了 |
| `cost` | 要加钱 | 行李超重 / 房价不含早 |
| `change` | 流程变了 | 刷卡机坏了 / 要先化验 / 订单被系统取消 |
| `probe` | 被追问 | 你说得太笼统，举个例子 |
| `offer` | 对方提议 | 要不要加进楼栋群 |

分类不是为了做目录，是为了**诊断**：

```
实战接住率 52%          ← 说明不了什么
你卡住的三次里两次是「要加钱」   ← 指向下一步该练什么
```

`validate()` 会检查 `kind` 合法，写语料时忘了标会当场报错。

### 记账：只记类型，不记句子

`Progress.branchStats[kind] = { ok, n }`。实战走完把「这道岔路接住没有」交出去：

```ts
finishScene(id, score, words, 'live', { kind, ok })
```

接住＝照着某个参考说法打对；没接住＝从选项里挑了一个（退路不计分，但要记账）。

### 报告里怎么呈现

```
岔路 · 哪类意外最容易卡住        最弱：要加钱
要加钱    ▬▬▬▬▬▬▬▬▬▬▬▬▬▬                      1/4
东西没了  ▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬            2/3
流程变了  ▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬            2/3
被追问    ▬                                      0/1
```

三条规则：

1. **只练过一局的排最后**。样本不够，看了也不能下结论，排在前面反而把真正最弱的挤下去。
2. **「最弱」要两局以上、且接住率不到一半**。一局全错只是运气不好。
3. 正常的行条形压到 40% 不透明度，只让最弱那一行跳出来 —— 四行一样重，等于没有结论。

接住率低的类型也会自动进「接下来这样练」。

## 11. 进今日卷轴：文章 + 对话，各一项

首页原来只有「今日卷轴 · 一篇文章」。对话做出来之后，它每天只推文章；这件事有点荒唐：
最需要每天练一点的其实是开口。

### 抽取规则和文章一致

```ts
pickDailyScene(scenes, unlocked, day)  // 日期做种子，只从已解锁难度里抽
```

同一天刷新多少次都是同一场；换一天换一场（30 天能覆盖全部 10 场）。

### 两项分开记，连续天数共用

```ts
p.dailyArticle / p.dailyDone          // 文章
p.dailyScene   / p.dailySceneDone     // 对话
p.dailyStreak  / p.dailyLastDay       // 两项共用
```

为什么不要求「两项都做完」才算一天：那等于把门槛翻倍，多数人第一天就断了。
现在的规则是**开张即算**——做哪一项都推进连续天数，另一项只是加分。

`bumpDailyStreak()` 抽成了纯函数（昨天 +1 / 今天不重复加 / 断了从 1 重来），
文章和对话两条路径都走它，测试直接覆盖三种情况。

### 直达，而不是让用户自己找

首页那一行点下去，**直接打开那一场**，不用回列表挑：

```ts
openScene(id)          // screen='dialogue' + pendingScene=id
consumePendingScene()  // 对话页挂载时取走并清空
```

中间踩了一个坑：`ensureDaily` 原本只在「跨天」时写档，而对话语料比文章晚加载一帧，
第一次写入时场景 id 还是 null，之后又不满足跨天条件 → `dailyScene` 永远是 null，
进度看起来正常（界面用的是即时算出来的 id），但结算时永远对不上。
改成每次都调、由 `ensureDaily` 内部比对去重。**界面好看不代表记账是对的**。

## 12. 代码结构

五种练法挤在一个文件里时，`DialogueScreen.tsx` 到了 1090 行——改跟读要滚过整个跟打，
改岔路要先确认不会碰到背诵。现在按「一种练法一个文件」拆开：

```
screens/DialogueScreen.tsx   列表 + 场景外壳（挑场景、切模式、传参数）  235 行
screens/dialogue/shared.tsx  模式表 / PracticeProps / 进度条            32 行
screens/dialogue/Reader.tsx  通读（气泡 + 连播）                        71 行
screens/dialogue/Drill.tsx   跟打 / 背打（同一个组件，差一个 shown）     201 行
screens/dialogue/Speak.tsx   跟读（麦克风 + 降级）                     222 行
screens/dialogue/Live.tsx    实战（时间线 + 岔路）                     312 行
lib/dialogue.ts              纯逻辑（比对 / 判分 / 时间线 / 校验）      可被 Node 直接测
```

拆分本身不改任何行为：89 项端到端断言在拆分前后完全一致。
顺手把三处重复的进度条（跟打、跟读、实战各写一遍）合并成 `StepBar`。

真正的收益不是行数，而是**改动的爆炸半径**：现在改岔路只影响 Live，
改 ASR 只影响 Speak，改比对逻辑只影响 `lib/dialogue.ts`（且有单测守着）。

## 13. 自定义导入：让 10 场变成 10 个示例

内置 10 场是**示例**，不是天花板。课本里的对话、自己写的台词、工作邮件里的句式，
都可以粘进来用同一套练法。

### 格式只有一条

```
# 咖啡店点单                                 ← 场景名（可省）
> 工作日的早晨，街角咖啡店                    ← 情境说明（可省）
店员: Hi, what can I get started for you? | 你好，想喝点什么？
我: Could I get a large latte, please? | 我要一杯大杯拿铁，谢谢。
```

**「我:」标出你要练的那一方**，其余任何角色名都算对方（多个对方角色会合并成一个）。
分隔符 `|` 可以写成全角 `｜`，冒号可以是中文 `：`。

### 为什么中文不能省

背打拿中文当题干，实战拿中文当目标。只有英文的话，这两种练法就退化成抄写 ——
与其偷偷降级，不如在解析阶段直接要求补上。错误措辞也照这个逻辑写：

```
第 5 行缺中文 —— 写成「店员: 英文 | 中文」
```

### 宽容在哪、严格在哪

| 宽容 | 严格 |
|---|---|
| 中文冒号 `：`、全角竖线 `｜` | 英文里有全角字符 → 报错（判分按字符比，全角永远对不上） |
| 弯引号 `’ “ ”`、破折号 `—` 自动折成 ASCII | 中文里没有汉字 → 报错（多半是把英文贴到了中文那栏） |
| 空行、`//` 注释行忽略 | 缺 `|` 分隔 → 报错并给出行号 |
| 多写几个对方角色 → 合并 | 没有 `我:` → 报错并说明怎么标 |

解析器是纯函数（`lib/custom.ts`），界面只是把它接上：边写边校验，有错就禁用导入按钮。

### 没有岔路怎么办

自建场没有 `branch`，`timelineOf()` 早就按「没有岔路就返回一条直线」写好了，
所以实战自动退化成整场走一遍 —— 步数 = 台词数，结算照常。

这不是事后补的兼容，是第一版就把 `branch` 设计成了可选字段。**结构上留的可选项，
半年后会替你省掉一次重构。**

### 存储与删除

自建场景存在 `Progress.customScenes` 里，和内置语料分开：
内置的随版本更新，自建的永远不动。删除时连 `p.scenes[id]` 一起清掉 ——
否则体检报告里会留着一场「练过但不存在」的对话。

## 14. 句型复习：整块句子也进间隔重复

单词有 FSRS，句型没有。可口语里最该背的恰恰是整块说法：
「Keep the change」记住的是四个词连在一起，不是 keep + the + change。

### 收池规矩：练过那场，它的句型才进池

一上来就把 40 个句型全塞进复习队列，第二天就放弃了。所以：

```ts
unlockedPhrases(scenes, sceneStats)   // 只收「练过」的场景
```

练完一场 → 那场的 4 个句型进池 → 之后按 FSRS 到期复习。

### 一轮抽什么

```ts
pickSession(pool, stats, today, 8)
  = 到期的（due 越早越前）+ 没学过的（按池子顺序），取前 8
```

只考到期，池子会停在最初那几句；只考新的，学过的永远不复习。两者都要。

### 一个必须冻结的东西

```tsx
// 错：每次渲染都重算
items={pickSession(pool, p.phrases, dayNo(), 8)}

// 对：点开始时定死
setSession(pickSession(pool, p.phrases, dayNo(), 8));
```

因为**答题会立刻改写 `due`**：答对一句，它就从「到期」变成「四天后」，
重算的下一帧题单就少了一句 —— 用户会看到进度条从 4 变成 3，然后卡在第 4 题上。

这是测试抓出来的：前 3 句都对，第 4 句判分时 `items[i]` 已经不存在了。
**凡是「每答一题就改数据」的会话，题单必须和状态解耦。**

### 交互

看中文 → 打整句 → 判分（复用 `diff`，标点大小写不计）。说错亮原句和 tip，
回车继续。结算显示 `N 句里说对 M 句`。

入口在对话列表顶部：`8 句待复习 · 来自你练过的 2 场对话 · 共收 8 句`，
全部复习完就显示「今天的句型都复习过了」。

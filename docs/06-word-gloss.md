# 释义贴合：同一个词的"两本账"

> 起因：文章里 `an unknown stranger` 下面的胶囊写着 `stranger a. 奇怪的, 陌生的`。
> 用户问：这文章和翻译怎么都这么怪？

## 1. 三种"怪"，三种不同的原因

被指出的那一屏，其实是三个独立问题的叠加：

| 现象 | 是不是 bug | 根因 |
|---|---|---|
| 文章读着没头没尾 | 设计取舍 | 一本书按 ~125 词切成 80 段，各段独立成篇 |
| 译文生硬（"你的反对就成倍地涨"） | 质量问题 | 逐句直译，句句对原文，缺上下文润色 |
| `stranger a. 奇怪的` | **是 bug** | lemma 归一覆盖了它自己的词条 |

前两条见 `LICENSE-NOTICE.md §5` 与 `docs/05-translation-qa.md`；本文只讲第三条。

## 2. bug 是什么

ECDICT 里 `stranger` 有两条信息：

```
stranger   n. 陌生人, 门外汉            ← 它自己的条目
strange    a. 奇怪的, 陌生的, ...       ← 它的"原形"（exchange 写 0:strange/1:r）
```

`lemmaOf()` 先查 `lemma.json`，`stranger → strange` 命中就直接返回，**再也回不到 `stranger` 自己的条目**。
于是句子里明明是个名词，释义却来自形容词 `strange`。

同类词一共 **51 个**，在 1156 篇正文里出现 **2715 次**：

| 词 | 自己的条目 | 被错显示的 | 正文出现 |
|---|---|---|---|
| born | a. 天生的 | n. 熊（bear） | 17 |
| tired | a. 疲累的 | n. 轮胎（tire） | 8 |
| evening | n. 傍晚 | a. 平坦的（even） | 26 |
| means | n. 方法 | a. 低劣的（mean） | 17 |
| stranger | n. 陌生人 | a. 奇怪的（strange） | 15 |
| united | a. 联合的 | vi. 接合（unite） | 13 |
| provided | conj. 倘若 | vt. 提供（provide） | 7 |

`saw`（94 次）是反例：它自己有条目 `n. 锯子`，但文中九成是 see 的过去式——
**不能一刀切"用自己那本账"**，得看句法。

## 3. 规则：先看句法，再看词形

`pickZh()` 现在按前一个词判断这个词在句子里干什么：

| 前一个词 | 判断 | 翻哪本账 |
|---|---|---|
| I / he / they / can / will | 谓语动词 | 原形（I saw → see） |
| than / much / far / even | 比较级 | 原形（stranger than → strange） |
| was / is / were | 表语 | 自己（was born → a. 天生的） |
| a / the / in / of | 名词 | 自己（the evening → n. 傍晚） |
| 冠词 + 后面紧跟名词 | 定语 | 自己（an unknown stranger → unknown 取 a.，stranger 取 n.） |

两本账**分开翻**：先在自己条目里按信号找完，确实没有再翻原形。
`a stranger harpooneer` 里 stranger 没有形容词义项，它就是个名词，不该顺着 strange 借一个 `a. 奇怪的` 过来。

词形规则（`-ed/-ing → 动词`、`-er → 比较级`）只在句法给不出信号时才用，
且**有独立条目的词不按比较级处理**——否则 stranger、longer、others 全会被当成比较级。

## 4. 义项顺序：词典的第一条不等于常用义

`multiply` 的释义是 `v. 繁殖, 乘, 增加`，"繁殖"排第一。摆在
`then your objections indefinitely multiply`（抵触成倍增加）下面就荒谬了。

这不是句法能解决的——三个义项都是动词。所以留了一张人工表：

```ts
const GLOSS_HINT: Record<string, string> = {
  multiply: '增加',
  objection: '反对',
  unfamiliar: '不熟悉的',
  according: '根据',
};
```

命中就只取那一个义项，不命中走正常流程。**表只收实测中真被误解的词**，
不做成第二本词典——一旦扩大，它就会和数据源一样难以维护。

## 5. 顺手修的两处

- 生词胶囊点击发音用的是 `g.key`（归一后的原形），点 `stranger` 会读成 `strange`。改成 `g.surface`。
- 胶囊音标取的是原形条目的音标，同样改成优先用自己的。

`scripts/test-gloss.mjs`（已并入 `npm test`，第 3 步）：

2. **整句测试**：截图那一句跑一遍 `glossOf`，stranger 不能出现"奇怪"。
3. **全库哨兵**：扫 1156 篇每篇前 4 句，`born→熊`、`tired→轮胎`、`evening→平坦`、

   命中即失败。

```bash

```

## 7. 还没有解决的

- **同一词性内部的义项顺序**仍然靠 `brief()` 取前三条。§11 解决的是「该翻哪本账、取哪类词性」，
  但 multiply 的 vt. 一行里「乘」排在「增加」前面，这种同词性内部的排序还是改不了 ——
  ECDICT 没有义项级词频。现在靠 `GLOSS_HINT` 手动覆盖 4 个词。
- **同书跳段**：一本书的 80 段被按难度分到 7 个城区，每个城区只剩 8–16 段。
  续读能够保证"方向不倒退"，但同城区内仍可能从第 19 段跳到第 72 段。
  要真正连贯，得按原文顺序重新分层（会改动 `lv`，牵涉解锁进度，暂缓）。

## 9. 维基那批条目换了一次
原来的 44 篇来自随机接口，28 个条目里有：

- 不适宜：`Pubic hair removal`
- 敏感：`Abortion debate`、`Expulsion of Palestinians from Kuwait (1990–91)`
- 冷门小传：`Anton Ondruš`（斯洛伐克球员）、`Jordi Gordillo Brunet`、`Mirian III of Iberia`
- 流行文化琐事：`Taarak Mehta Ka Ooltah Chashmah`、`CBeebies`

长城、折纸、南极洲、蒸汽机、月球、撒哈拉、轮子、爵士乐、太阳系。

流程是 `--plan` 抓取切段 → 人工逐句翻译 → `import-tr.mjs` 事务式合入 → `--apply` 替换。

清洗规则（只处理解析残留，不改语义）：

| 规则 | 拦下的东西 |
|---|---|
| 清 `== 小节标题 ==`、`''斜体''` | `== Species == Honey bees are…` |
| 句长 < 4 词或 > 45 词即弃段 | `A. mellifera` 被切断、`Porcelain … Spices Paper …` 罗列 |

## 10. 全量重译之前，先修了切句

用户要求"全量重译 5600 句"。真跑之前先做了两件事：抽样定级、量一下到底坏在哪。

### 抽样：36 句，每本书 3 句

结论是**译文整体没有问题**，36 句里只有 1 句明显译错。典型质量：

```
EN   MRS. Rachel Lynde lived just where the Avonlea main road dipped down…
ZH   雷切尔·林德太太就住在埃文利大路往下陷进一个小洼地的那个地方；…
```

长句反而翻得细。所以"逐句重译 5600 句"是拿 100% 的工换 3% 的收益，还会引入新错。

### 长句审校：95 句（≥62 词）

按句长降序审完全部 95 句，改 5 处（5.3%），都是"个别词不准"而不是"看不懂"：

| 句 | 原译 | 改 |
|---|---|---|
| `study in drab of one kind` | 乏味人性的绝妙研究 | 灰色调的绝妙人物素描 |
| `keeping his arm in sun and shade` | 晒惯了他的胳膊 | 胳膊时而晒着、时而阴着 |
| `by the score` | 成二十条 | 成打成打 |
| `excited so little curiosity` | 激起了如此微小的好奇 | 没起多少好奇 |

工具：`scripts/export-long.mjs`（按句长导出）+ `scripts/fix-tr.mjs`（单句改写）。

### 真问题：切句在标点后就断

扫描 5446 句，发现 **154 处**误断 —— `BOUNDARY_RE` 只要「标点 + 空格」就断，于是：

```
Alas! ｜ it was too late to wish that!
「唉！」 ｜ 「可这会儿再盼也来不及了！」
```

屏幕上就是一句孤零零的感叹，看着像翻译坏了，其实是被切坏了。

修法：句界后面必须紧跟大写字母/引号/括号。

```js
// 旧
const BOUNDARY_RE = /[.!?]+["'\u201d)\]]?\s+/g;
// 新
const BOUNDARY_RE = /[.!?]+["'\u201d)\]]?\s+(?=["'\u201c(]|[A-Z])/g;
```

**这会改变句数，必须同步重组译文数组**。`scripts/remerge-tr.mjs` 按字符区间做映射：
新句横跨几条旧句就把那几条译文直接拼起来（它们本来就是一句话的两半），映射不上一律报错不写。

结果：5600 → **5446 句**，115 篇受影响，合并 154 处误断。
碎片（≤4 词）从 279（5.0%）降到 186（3.4%）；剩下的多是英文本身的多感叹句
（`Oh dear! I shall be late!`）和对话轮次，属于正常切分。

### 最终进度

| 覆盖面 | 句子 | 方式 | 改动 |
|---|---|---|---|
| ≥62 词 | 95 | 逐句审完 | 4 |
| 51–61 词 | 142 | 逐句审 58 句 | 1 |
| 33–40 词 | 495 | 逐句审 62 句 | 1 |
| ≤32 词 | 4387 | 抽样 60 句 | 1 |
| **全库 5446 句** | 5446 | 引号类型扫描 | **31** |
| 合计 | | | **38** |

长句逐句审了 215 句（最长的那 4%），发现 6 处。剩下 5231 句靠两种方式覆盖：
类型扫描（全库）+ 分层抽样（60 句，每本书 2 句）。

抽样结论：短句几乎全合格，60 句里只有 1 句读着不顺（「被…震动了」）。
越短的句子越不容易翻错，这也解释了问题率随句长单调下降。

## 11. 义项选择：四级信号 + 一把尺子

§1–§6 修的是「翻错账」（stranger 拿了 strange 的形容词）。这一轮修的是另一半：
**账翻对了，但取的词性不对**。

### 先量，再改

没有量具就只能凭手感改规则。`npm run audit:gloss` 把全库 1.2 万条释义按
「形态应该指向的词性」对一遍：

| 类 | 判据 |
|---|---|
| -ly 给了动词/名词 | 副词丢了 |
| 该是动词却给了名词 | 前面是主语代词 / 情态动词 / to |
| 该是名词却给了动词 | 前面是冠词 / 介词 |
| -ing/-ed 给了名词 | 动名词算对，所以这类只统计不判错 |

每条都先问「词库里到底有没有那一类义项」—— 没有的算词库缺口，不算挑错。
否则 `to supper`（sup 没有动词义项）会把数字撑得没法比较。

### 改前改后（同一把尺子）

| 类 | 改前 | 改后 |
|---|---|---|
| -ly 给了动词/名词 | 24（0.20%） | **0** |
| 该是动词却给了名词 | 107（0.90%） | **0** |
| 该是名词却给了动词 | 0 | 0 |
| -ing/-ed 给了名词（动名词，仅统计） | 206（1.73%） | 121（0.97%） |

顺带：会显示的释义从 11942 涨到 12423 —— 481 个 -ing/-ed 词以前被整条跳过
（`coming` 只有名词义项，与其误导不如不显示），现在能顺着词根找到动词义项，就显示出来了。

### 四条新信号

1. **缩写展开**。`I'm` / `we've` / `it's` 不展开，前面的系动词、助动词信号全丢 ——
   「I'm opening」于是被当成「opening = n. 开始」。
2. **to + 实词 = 不定式**。`to protest` 是动词，`to school` 是介词短语。
   一张 23 个词的小例外表挡住后者。
3. **be/have + -ing 先找动词**（I'm opening），+ -ed 仍让形容词优先（was tired）。
4. **-ly 排在句法信号之前**。「it was earnestly said」里前一个词是 it，
   但 earnestly 还是副词。只是**排在前面**，不是独占 —— supply / reply / apply 也以 -ly 结尾，
   前面出现情态动词时仍要按动词处理。

### 词根兜底

`making` / `opening` / `coming` 在 ECDICT 里**自成词条**，`lemma` 也是它自己，
于是永远只看得到它们的名词义项。`baseOf()` 往词根再找一层，只取带动词义项的那本：

```
be making → making 自己的条目只有 n. 制造
          → 词根 make 有 vt. 制造 ✔
```

### 一个失败的尝试：全局按词性优先

第一版把搜索改成「先按词性找，再按账找」，结果 `an unknown stranger` 借到了
strange 的 `a. 奇怪的` —— 因为 stranger 自己的 n. 陌生人 排在第二个词性优先级上，
而 strange 的 a. 排在第一。

正确的做法是**两级**：先在「自己的账（含词根）」里按词性挑，找不到再去「原形的账」。
账的优先级高于词性，词性的优先级高于行序。

这条被 §6 的回归测试当场抓住（`stranger` 那条断言要求不含「奇怪」）。
**改规则之前先跑测试，不是形式**。
